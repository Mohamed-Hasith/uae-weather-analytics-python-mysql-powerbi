UAE WEATHER | POWER BI DESKTOP

1. Extract the whole ZIP to a local folder on the Windows PC running MySQL. Keep Weather.pbip next to both folders. Do not open files inside the ZIP.
2. Open Weather.pbip in current Power BI Desktop. If Desktop asks you to enable Power BI project files, enable that option and restart Desktop. If the MySQL provider is missing, install Oracle MySQL Connector/NET and restart Desktop. See https://learn.microsoft.com/en-us/power-query/connectors/mysql-database .
3. Click Home > Refresh. For 127.0.0.1, choose Database authentication and enter your MySQL username and password in Desktop only. A user with SELECT permission on uae_weather_analytics.hourly_forecasts is sufficient. If prompted, review and approve the two native SELECT queries (also included separately). No tables or views are created or changed. No weather records or credentials are bundled. If the host/database differs, use Transform data > Advanced Editor in both queries to edit the first two MySQL.Database arguments.
4. Select a city on page 1. A complete newest batch is 24 hours per city, 96 rows with all four cities. Line values are averages across selected cities. Last collection is the time from MySQL, not the time the report file was opened. For a partial batch, this page deliberately shows only rows in that batch, never older rows substituted for missing cities.
5. On page 2, select one city and one forecast hour. Choose an hour covered by multiple runs. The line follows predictions for that same hour as collection time advances; it remains blank for ambiguous selections. Revision delta is the temperature difference from the preceding available collection for that city/hour in the seven-day history window. The first comparison is blank, not zero. These are forecast revisions, not errors against observed weather.
6. After the next successful hourly Task Scheduler run, click Home > Refresh again and compare Last collection with SELECT MAX(collected_at) FROM hourly_forecasts; in Workbench. Save the report after importing. Free Desktop does not automatically refresh this imported model every hour; the scheduler updates the database only.

Measures.dax lists the ten measures already installed in the model. You do not need to paste them. The model reads only hourly_forecasts and assumes the shared collected_at timestamp per run and column names described in your project handover. It requires MySQL 8 or newer for the revision query.
